# 影研社（Image Lab）

一个面向医学影像学习者的静态教学网站，无需登录或安装。访问 [公开网站](https://a1553189184-stack.github.io/medical-imaging-learning/)。

## 功能

- 病例图谱：700 个真实开放影像病例（胸部 185、神经 173、腹部 172、骨骼 170），包含 X 线、CT / CTPA、MRI、超声和骨显像。每例有中英文名称、影像征象、分步骤诊断方法、阅片技巧、鉴别诊断与易错点、报告表达练习、记忆线索和参考资料。依据独立来源说明进一步拆分疾病与影像亚型，四系统教学主题分别达到胸部 113、神经 111、腹部 115、骨骼 126 个。
- DICOM 序列阅片：20 个来自 NCI Imaging Data Commons 的去标识独立检查，四系统各 5 个。站内 Cornerstone3D 工作台支持真实层面滚动、窗宽窗位、平移、缩放、长度测量和序列切换；OHIF 保留为完整备用查看器。集合名称不作为逐图诊断。
- 组合筛选：系统、影像类型、难度、学习状态及收藏；支持搜索疾病名称与征象，并将当前筛选结果直接用于背题或答题。
- 答题模式：单选诊断题，提交后显示正确答案与完整解析；提交前隐藏标题和跳题菜单中的诊断名称。
- 背题模式：直接对照选项、参考答案、诊断方法和技巧；可收起答案进行回忆，也可独立标记“已背”。
- 分阶段阅片：按“描述所见 → 诊断判断 → 报告训练”完成病例；所见草稿和结构化报告自动保存在本机，并随学习记录导出、导入。
- 病例专属推理追问：每例按“定位 → 表型 → 鉴别”完成三个苏格拉底式检查点；作答前只显示问题，提交诊断后才显示由该例诊断方法、关键征象和鉴别要点生成的参考路径。完成状态与自由文本分开记录，不把完成度冒充医学正确率。
- 分级引导：可选择医学生、住院医师或进阶层级，在作答前逐级获取定位、影像表型和鉴别诊断提示；提示强度和使用次数透明显示。
- 报告训练：分别填写定位、影像所见、诊断印象与下一步建议。本地规则只检查结构完整度和参考诊断术语命中，并明确不代替医学正确性审核。
- 同主题影像对照：在作答后或背题模式中并排查看相近病例；对照图均标明为不同公开病例，避免误当作同一患者的连续序列。
- 病例包完整性：700 例均生成版本化病例包，SHA-256 指纹覆盖病例内容、教学计划和本地影像字节；完整性、来源核验和医学审校是三种独立状态。
- 智能选题与排序：顺序、随机、自定义；支持病例搜索、系统与病种筛选、每病种随机抽取 N 例、快速 10 题、薄弱项专项、拖动及上下移动排序。
- 本地保存与备份：题目列表、模式、排序、当前位置及本轮已提交答案在刷新后保留；笔记、推理追问、所见草稿、结构化报告、收藏和完成状态都绑定稳定病例 ID。学习进度可导出为 JSON，并在其他设备导入合并。提示、推理检查点、作答、报告评分和背题标记另存为不含影像及自由文本的本地审计事件。
- 错题复习：记录每例实际作答次数、错误次数及最近一次答案；答错加入待复习，重练答对后移出。可从学习进度一键重练/背诵错题，也可通过图谱和选题窗口筛选。
- 透明学习处方：只根据本机已有的最近答错、历史错误、提示使用、报告结构分和推理检查点生成按病种归纳的复习建议；未答题病例不被贴上薄弱标签。可一键开始不重复的 10 题处方训练，或只练某一主题。
- 间隔复习计划：从新提交的每次答题开始，答错安排今日复习，连续答对按 1、3、7、14、30 天间隔安排下一次复习；今日到期病例可一键练习或背诵。旧版历史记录不倒推虚构日期，计划随学习记录导出、导入。
- 系统表现：按胸部、神经、腹部、骨骼显示逐题首答正确率与当前错题数；只使用本机已有的逐题首答事件，旧版总成绩不会被臆测拆分，并可直接复习某系统当前错题。
- 静态影像工具：对比度、缩放、反相和位置标注，保留原图比例及原始注释。
- 性能：图谱采用 700 张独立 WebP 缩略图并每次加载 48 例；缩略图总量约 8.6 MB，详情和训练继续使用原始影像。
- 真实学习统计与桌面、平板、手机布局，不预置身份、连续天数或演示成绩。

## 如何使用

1. 在“病例图谱”点击“诊断方法与详情”阅读完整资料；不用先答题才能查看。
2. 想记忆病例时，选择“背题”或在“阅片训练”顶部切换“背题模式”。点击“收起答案”进行回忆，再展开核对。
3. 点击“选择题目与顺序”，勾选需要的病例，用上下箭头排列，并选择学习模式后“应用并开始”。也可以直接选择随机顺序，或在“跳到”菜单中切题。
4. 笔记自动保存到对应病例。背题标记不计入答题数或正确率，正确率只统计每例第一次提交。重新开始训练可再次作答，但不会改写首次成绩。

随机顺序在本轮内不重复；到最后一题显示学习小结，不强制循环。应用新的题目列表会开始新一轮，历史笔记、收藏和首次成绩保留。取消选题窗口不会改变当前列表。

错题状态以最近一次已提交答案为准，“标记已背”不会清除错题。历史错误次数保留，首次判断正确率也不会被重练改写。升级时只恢复旧版本现存的本轮逐题答案；没有逐题记录的更早错误，不能从总分倒推出具体病例。

快捷键：左右方向键切题，1–4 选择选项，A 标注，R 重置影像，Ctrl / ⌘ + K 搜索。编辑笔记时不会触发切题快捷键。桌面上选择对比度或缩放工具后，可在影像上使用鼠标滚轮。

## 内容边界与数据保存

影像为下载到站内的公开教学图片，来源、作者及许可见 [IMAGE_SOURCES.md](IMAGE_SOURCES.md)。扩展的 686 例在详情页直接展示 Commons 原始文件名、来源诊断说明、许可、文件页及 SHA-1 指纹；本地清单另存 SHA-256 供发布前复核。页面明确显示“来源核验完成”和“放射科医师逐例审校待完成”，不能把来源标签误作专家审校。

DICOM 试验区的 20 个 Study UID、集合 DOI、模态和许可见 [DICOM_SOURCES.md](DICOM_SOURCES.md)。DICOM 文件不复制到本站，由 IDC 按需加载。

原有 14 例的年龄、症状等临床情境是教学编写，不是原图患者病历；扩展的 686 例不补造病史，只训练来源能够支持的影像征象。单张图的局限在每例中单独说明；图片中的箭头和测量标记来自原始文件。图谱中的征象概括与训练答案不能替代完整序列、病史、体检或临床诊断。

700 例静态题库本身不托管 DICOM，因此题库内的“对比度”只调整图片显示，不能提供真实窗宽窗位、校准长度或 HU。真实调窗、层面滚动与测量仅在单独的 DICOM 序列试验区中由 Cornerstone3D 或 OHIF 对 IDC 原始检查完成。

所有记录默认保存在当前浏览器的 `localStorage`，不会自动跨设备同步。可以在“学习进度”导出 JSON，并在另一设备导入合并。清除站点数据前应先导出备份；浏览器禁止存储时只能临时使用。不要在笔记中录入可识别患者身份的信息。

## 运行

日常访问无需构建，可在目录中启动本地静态服务器：

```bash
python -m http.server 4173 --bind 127.0.0.1
```

浏览器打开 `http://127.0.0.1:4173/`。公开版本通过 GitHub Pages 部署；旧的 `?case=4` 链接仍可进入训练，`?view=cases` 打开图谱，`?view=caseDetail&case=4` 打开详情。

若修改 `src/cornerstone-viewer.js`，需先安装锁定依赖并重新生成浏览器资源：

```bash
npm ci
npm run build:viewer
```

影像引擎仅在用户点击“站内打开序列”后加载，不影响图谱和训练首页的初始下载。

## 文件组织

- `cases.js`：影像文件、题目、诊断选项及基础解析。
- `curriculum.js`：按稳定病例 ID 关联的诊断方法、技巧、记忆线索、影像限制及参考资料。
- `expanded-sources.js`、`expanded-cases.js`、`additional-groups.js`、`next-76-groups.js`、`next-200-groups.js`、`next-200-review.js`：扩展 686 例的来源记录与按疾病编写、复核的教学内容。
- `dicom-series.js`、`idc-dicomweb.json`、`DICOM_SOURCES.md`：20 个 IDC 检查及 Cornerstone3D / OHIF 共用的只读 DICOMweb 配置和来源说明。
- `src/cornerstone-viewer.js`、`vite.config.mjs`、`assets/cornerstone/`：站内 DICOM 工作台源代码、锁定构建配置和发布资源。
- `medical-reviews.js`、`MEDICAL_REVIEW.md`：临床专家签名审校登记与逐例审校规范；未登记的病例不会显示“医学已审”。
- `case-packages.js`：自动生成的700例版本化完整性清单，关联病例内容、教学计划与影像 SHA-256。
- `scripts/generate-case-packages.mjs`：病例包生成器；修改病例、课程或图片后必须重新运行。
- `data/expanded-case-sources.json`：机器可读的来源、许可、原文件与本地文件校验清单。
- `app.js`：筛选、详情、训练模式、选题排序、本地记录与影像交互。
- `index.html`、`styles.css`、`learning.css`：页面结构及响应式样式。
- `assets/images/`：原始开放影像，许可不因网站发布而改变。
- `assets/thumbnails/`：病例图谱专用轻量 WebP 缩略图，由 `scripts/generate-thumbnails.py` 从原图生成。

新增病例时，影像文件名（去扩展名）须与课程 ID 对应，并维护来源说明。首页分类数量、图谱总数和进度分母由题库自动计算。现有记录与原始病例顺序兼容，不应随意调换 `cases.js` 中既有条目，新病例应追加到末尾。

## 内容一致性检查

安装 Node.js 后运行：

```bash
node --test tests/catalog.test.cjs
```

检查 700 个题目与课程一一对应、扩展病例数量、选项和必需字段、图片文件格式、旧病例顺序、686 个来源及文件指纹唯一性，以及病例包中的内容、课程与图片 SHA-256 是否可重新计算并逐一吻合。新增 200 例另经过联系表目视审查和近似图像哈希筛查。这是来源与数据一致性检查，不代替医学专家审校。

启动本地静态服务器后可运行真实浏览器流程检查：

```bash
node tests/browser-smoke.mjs
```

该检查覆盖分级提示、防提前泄露、答题、报告评分、病例包显示、本地事件隐私边界和移动端横向溢出。

联网核对 20 个 DICOM Study UID：

```bash
npm run audit:dicom
```

启动本地静态服务器后，验证真实 IDC CT 多层序列、Cornerstone3D 渲染、测量工具和移动端宽度：

```bash
npm run test:dicom
```

## 开源设计参考

- [OHIF Viewer](https://github.com/OHIF/Viewers)：专业阅片工作台的信息层级与工具组织
- [Cornerstone3D](https://github.com/cornerstonejs/cornerstone3D)：Web 医学影像交互能力与 DICOMweb 扩展方向
- [CaseAttend](https://github.com/JamesWeatherhead/CaseAttend)：版本化病例包、教学计划、分级引导、审核状态和本地学习事件的设计思想
- [VibeRad](https://github.com/JamesWeatherhead/VibeRad)：用户主动截取当前视野后再向视觉模型提问的交互边界
- [RadDiagVQA](https://github.com/QingxiaWu21/RadDiagVQA)：放射影像问答题型与评测设计；不直接再分发其受第三方版权约束的内容
- [Anatria3D](https://github.com/Nurkan1/Anatria-3D)：本地优先学习记录、资产来源分层和未来影像—解剖联动方向
- [RadGame](https://github.com/siavashraissi/RadGame)：病例驱动、游戏化反馈的影像教学方式

本站原创实现教学流程和数据结构，不复制其他项目的界面、病例或文字。当前 DICOM 试验区以 Cornerstone3D 按需读取 IDC 原始检查，并保留公开 OHIF Viewer 作为完整备用入口。本站仅用于教学，不用于临床诊断。
